# Triage

Move TaskNotes issues and tasks (and optionally external PRs) through a state machine of triage roles.

Start every comment or issue you post during triage with this disclaimer:

```text
> *This was generated by AI during triage.*
```

## Roles

- **Categories**: `bug`, `enhancement`
- **States**: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`

Read `docs/agents/triage-labels.md` for the label string mapped to each role. If it is missing, tell the user to run the
`setup-skills` skill.

## Process

1. **Show what needs attention.** Query the tracker (TaskNotes files under `.scratch/`, or the location in
   `docs/agents/issue-tracker.md`) and group items into unlabeled, `needs-triage`, and `needs-info`.
2. **Check prior rejections.** Before triaging an enhancement, read
   [references/OUT-OF-SCOPE.md](references/OUT-OF-SCOPE.md) and compare the request against `.out-of-scope/`.
3. **Triage each item.** Read its context, verify its claims against the codebase, and grill the reporter (via the
   `grilling` skill) if key facts are missing. Then apply one outcome state:
   - `ready-for-agent`: first read [references/AGENT-BRIEF.md](references/AGENT-BRIEF.md) and write the agent brief it
     describes.
   - `wontfix` for a rejected feature: record it in `.out-of-scope/` as
     [references/OUT-OF-SCOPE.md](references/OUT-OF-SCOPE.md) describes.
   - `needs-info`, `ready-for-human`: comment with what is missing or why a human is needed.
4. **Keep TaskNotes valid** (local tracker only). Every touched file keeps the TaskNote format and field rules in
   `docs/agents/issue-tracker.md`; bump `dateModified` on each edit, and close rejected items as that doc's **Won't do**
   describes.
